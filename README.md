# tradeclerks.com

Holding page, Terms and Privacy for the Trade Clerks app, the customer page (`/v/`) and the return pages for Google and Stripe.

**Where it's served from.** The site is moving from GitHub Pages to Cloudflare (site PR S1; the app repo's `docs/plans/WEBSITE_PLAN.md`, section 5). Until the last step of the move both are set up: every merge to `main` is built by both, and `tradeclerks.com` is answered by GitHub Pages until the switch and by Cloudflare after it. Cloudflare serves plain files and runs no code of ours: its build runs `node make-dist.mjs`, which copies the published files, and only those, into `dist/`, and `wrangler.jsonc` tells it to serve that folder. `make-dist.mjs` lists every published file and every working file that is never served; `_config.yml` tells GitHub Pages the same. `node --test tests/published-files.test.mjs` holds the two together, and fails when a new file is in neither list. Agents working here read `AGENTS.md` first.

- The legal text lives in `content/*.md`, copied from `docs/legal/` on the app repo's `main` (the source of truth): `terms.md` and `privacy.md` by name, nothing else from that folder, never from an unmerged branch.
- To change it: copy the two files in, and set the effective date in the copies only (the source keeps `[publish date]`) to the day Steve will merge. Check each copy differs from the source only on that line and shows the same version as the app's `TERMS_VERSION`. Run `python3 build.py`, then open a pull request. If the merge moves to another day, change the date in both copies and rebuild before merging.
- A merge or push to `main` publishes the site straight away (GitHub Pages, and Cloudflare once it is connected), so nobody pushes to `main`, and only Steve merges.
- The customer page (`v/index.html`) shows an invoice or quote from the link in the email. An open quote's total is worked out on the page as the customer ticks options, and must equal what the server stores on acceptance (each tax rounded to the cent on its own, a half cent up). That working-out sits between the `@quote-total` marks and is tested: `node --test tests/quote-total.test.mjs` before any pull request that touches it. `tests/quote-cases.json` is a copy of the quotes the app repo holds its phone code and test database to (`supabase/tests/audit/65_money_rounding_test.sql`); a case changed there is copied here. When the test reports the copy check as skipped (no app repo found beside this one), run it again with `TRADE_CLERKS_APP=<path to the app repo>` before a pull request that changes the cases. `tests/` is never published (`_config.yml` and `make-dist.mjs`).
